# Политика безопасности

## Сообщение об уязвимости

Используйте [GitHub Private Vulnerability Reporting](https://github.com/HubbaBubbaPrepod/pulse-module-docker/security/advisories/new). Не публикуйте эксплойты, credentials, приватные адреса серверов или чувствительные журналы контейнеров в Issues. Укажите версии модуля, панели и агента, ОС и архитектуру, затронутое поведение, шаги воспроизведения, последствия и возможное снижение риска. Проверяйте только системы, которыми владеете или управляете. Срок ответа и SLA не обещаются.

Сообщайте о проблемах последнего релиза; при использовании старой версии проверьте [историю изменений](CHANGELOG.ru.md). График переноса исправлений в старые версии не опубликован.

## Доверие и права

Нативный сборщик выполняется с правами учётной записи агента без песочницы. Поле манифеста `permissions` описывает доступ и не ограничивает его. Сборщик делает запросы чтения, но доступ к Docker socket или Windows named pipe обычно даёт возможности уровня root на хосте. Предоставляйте доступ только доверенному агенту и устанавливайте пакеты из доверенного источника. Не открывайте Docker API в сеть ради модуля.

Скачивайте файлы из [релизов с тегами](https://github.com/HubbaBubbaPrepod/pulse-module-docker/releases), сверяйте `docker-module.json` с `checksums.txt` и при необходимости изучайте исходники. SHA-256 подтверждает целостность, а не доверие издателю. Не заменяйте выпущенные бинарники под прежней версией.

Журналы могут раскрывать секреты приложения или персональные данные. Осознанно выбирайте контейнер для журналов и ограничивайте доступ к панели. При компрометации пакета или учётной записи выключите назначение модуля, при необходимости остановите затронутый агент, сохраните свидетельства, замените раскрытые credentials и установите доверенный релиз перед возобновлением сбора.
