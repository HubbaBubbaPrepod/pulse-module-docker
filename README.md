# Pulse Module Docker

Native Docker Engine collector module for [Pulse Monitor](https://github.com/HubbaBubbaPrepod/pulse-monitor) and [Pulse Agent](https://github.com/HubbaBubbaPrepod/pulse-agent). Distributed as an uploadable JSON package. MIT licensed.

Docker-модуль — самостоятельный репозиторий и выпуск. Собирает версию движка, контейнеры, CPU/память, сетевые счётчики и последние журналы выбранного контейнера. Панель строит карточки, таблицу, графики и журналы по манифесту.

## Установка

1. Установите панель и агент, подключите реальный узел. Для первого публичного набора используйте Pulse Monitor v0.4.0 и Pulse Agent v0.4.0.
2. Скачайте `docker-module.json` версии **v1.0.1** и `checksums.txt` из [Releases](https://github.com/HubbaBubbaPrepod/pulse-module-docker/releases). Сверьте SHA-256: `sha256sum docker-module.json` или `Get-FileHash docker-module.json -Algorithm SHA256`.
3. В настройках модулей панели загрузите JSON-файл. В настройках нужного узла выберите Docker, заполните параметры и включите модуль.
4. Агент загрузит сборщик для своей платформы и выполнит его. Откройте раздел модуля в панели; для другого узла настройте отдельное назначение.

JSON содержит нативные сборки Linux amd64/arm64 и Windows amd64. Go и Node.js на узле для модуля не нужны; работающий Docker Engine и доступ агента к нему нужны. Пакет используют через панель, не как отдельную службу.

## Параметры

| Поле | Значение |
| --- | --- |
| `socket` | Путь Unix socket или Windows named pipe; пустое поле выбирает стандартный путь платформы |
| `logContainer` | Необязательный ID контейнера для последних журналов, минимум 12 символов |

Linux по умолчанию: `/var/run/docker.sock`. Windows по умолчанию: `\\.\pipe\docker_engine`. Для rootless Docker укажите путь socket своего пользователя и предоставьте службе агента доступ. На Windows проверьте, что выбранный Docker Engine доступен через named pipe учётной записи службы; наличие Docker Desktop само по себе не гарантирует доступ.

Список ограничен 100 контейнерами. Сеть показана накопительными счётчиками, а не скоростью. Журналы — последние 50 строк выбранного контейнера; сохранение полной истории контейнера модуль не выполняет. Доступность CPU/памяти зависит от статистики Docker. Графики показывают последние измерения в текущем просмотре.

## Права и безопасность

Сборщик делает запросы чтения, но Docker socket обычно даёт привилегированный контроль над хостом. Доступ к socket или pipe — значимые права, а не безопасная граница чтения. Не открывайте Docker API в сеть ради модуля.

Программа выполняется с правами агента, без песочницы. Описание `permissions` в манифесте не ограничивает ОС; SHA-256 проверяет целостность, но не доверие автору. Проверяйте происхождение пакета. Журналы контейнера могут содержать чувствительные данные.

## Обновление и удаление

v1.0.1 использует `schemaVersion: 1`, `protocol: 1`; его версия независима от версий панели и агента. Для обновления загрузите новый пакет с тем же `id: docker` и новой версией, проверьте назначения и результаты. Опубликованную v1.0.0 не заменяйте другими бинарниками с прежней версией: конфликт содержимого версии отклоняется. Сохраните текущий пакет и настройки перед обновлением.

Для остановки выключите назначение на нужном узле. Для удаления уберите модуль в настройках панели; остановленная конфигурация больше не выдаётся агентам. Кэш скачанных бинарников в состоянии агента может оставаться на диске; удаляйте его только при остановленном агенте и после проверки нужных путей.

## Сборка из исходников

Go 1.23+ и PowerShell 7.4+; Go в PATH либо через `-GoExe`:

```powershell
go test ./...
go vet ./...
./scripts/build.ps1 -Version 1.0.1
```

Результат: `artifacts/releases/docker-module.json`, `pulse-module-docker_v1.0.1_source.zip` и `checksums.txt`. Release-сборки используют выбранный проектом toolchain Go 1.27.2. Формат процесса: один JSON `{"protocol":1,"config":{}}` в stdin, один JSON-объект в stdout, код завершения 0. Диагностика — stderr; агент не передаёт его в панель. Лимит stdout — 512 KiB, скачивание и выполнение разделяют таймаут 5 секунд. [Полный протокол модулей](https://github.com/HubbaBubbaPrepod/pulse-monitor/blob/main/docs/MODULES.md).

## Диагностика и участие

`unsupported`: нет сборки для платформы. `error`: проверьте Docker Engine, socket/pipe, права службы, ID контейнера и таймаут. Недоступные журналы контейнера могут означать ограничение logging driver. Не запускайте два экземпляра агента с одним ID/токеном.
